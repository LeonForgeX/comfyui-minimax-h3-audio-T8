# DLSS 视频插帧 2x（EXP）

把本目录 JSON 拖进 ComfyUI，选择原视频，再执行。工作流在节点项目里，不需要去浏览器导出，也不会替换你打开的工作流。

它把 24fps 变成 48fps、30fps 变成 60fps：让运动更顺滑，分辨率、播放时长和原音轨保持不变。它不是超分，也不会缩短 H3 生成时间。可以接在扩画或超分保存的视频后面，但建议先分别确认效果。

## 需要什么

当前只支持 Windows、单张 NVIDIA RTX 显卡，且驱动和运行文件必须实际支持 DLSS Frame Generation。没有把 4060 Ti 的测试结果当成所有 RTX 都验证过。

自行准备上游 [ComfyUI-NVIDIA-DLSS-Frame-Interpolation](https://github.com/Konohamaru04/ComfyUI-NVIDIA-DLSS-Frame-Interpolation) 所用的这两个运行文件：

```text
ComfyUI/models/DLSS-FI/310.7.0/
  dlssg-worker.exe
  nvngx_dlssg.dll
```

默认读取这个目录；也可以把已安装的实际目录填入 `runtime_directory`。不要求额外下载 H3 模型或 LoRA，不需要同时安装上游节点插件。需要当前 Python 环境可用的 PyAV、NumPy、OpenCV DIS、psutil、pynvml；节点不会自动安装依赖、驱动或下载运行文件。

这是独立的插帧运行文件，不是已有 `models/DLSS-NR` 超分运行包。当前固定核对的是上游 c755e274a405a7a47667bd567d489b6845066bcf 版本所用二进制：

- worker SHA-256：`8a747f9ed613842d5b8b34a811ad43bc1a9466540e2e5a0c8ef4005f0db9e384`
- DLL SHA-256：`135eaf0733c1e37381a8c28abcf7a862404a54132b81787c04e35d09efc5e36f`

不匹配的文件会给出错误，不会假装插帧成功。需要用户自行取得使用运行文件的许可；没有协议勾选框，也不随节点分发 NVIDIA DLL 或闭源 worker。

## 参数

| 参数 | 作用 |
| --- | --- |
| `source_video` | 原生文件 VIDEO。若做过裁剪或截取，先保存为新文件再输入，防止处理时忽略编辑。 |
| `runtime_directory` | 运行文件目录，留空使用上面的标准位置。 |
| `cut_frames` | 硬切后第一帧的编号，从 0 开始。例如第 24 帧开始是新镜头，填 `24`；多个用 `24,48`。不自动检测硬切。 |
| `timeout_seconds` | 全部文件处理的最大时限，默认 600 秒。取消或超时只清理自己的子进程，不重试、不关闭其他软件。 |

成品保存到 ComfyUI 的 output 根目录，以 `H3_DLSS_FI_2x_` 开头。每次用新文件名，不覆盖原视频。`.dlss-fi-tasks` 保存中间文件和排错记录，占用空间；确认成品后可自行删除对应任务目录。

## 当前边界

- 文件必须是恒定帧率、8bit SDR、方形像素、偶数宽高、无旋转，源帧率不超过 60fps。暂不处理 HDR、10bit、VFR、旋转和内存帧批次，不偷偷转换这些输入。
- 当前采用保守的资源启动检查：至少约 12GB 空闲显存和 16GB 可用内存。这是本机验证的门限，不代表算法需要这么多显存，也不代表低显存显卡已获支持；不会自动卸载你的模型。
- 硬切间隔不生成混合帧，末尾保持一帧以维持时长。它们单独计数，不算真正生成的中间帧。
- 保留音轨的编码包、解码 PCM 和时间轴。最终视频用 H.264 CRF18 编码，所以不是逐像素无损保存。
- 当前保守检查会拒绝“输入有变化、中间帧却与端点完全相同”的区间；极小变化也可能触发拒绝。这是未覆盖情况，不靠复制源帧兜底。
- 快动作、遮挡、文字/HUD、闪光可能产生伪影；没有自动 HUD 保护承诺。游戏、固定字幕、闪光低纹理、显式硬切四组短片均被人审接受为相近可用，游戏组声音正常；其余三组为无声合成诊断片。随 1.77.0 以 EXP 提供，不外推所有视频质量，也不宣称人审证明了必然更流畅。
