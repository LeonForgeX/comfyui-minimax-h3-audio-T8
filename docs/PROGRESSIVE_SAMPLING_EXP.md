# H3 渐进分辨率首采（1.77.0 EXP）

先用较小的画幅生成结构，再用学习型潜空间放大模型放大，完成剩下的采样步骤。它尝试减少高分辨率计算量，不是对完成的视频做超分，也不是现有 VDN 的 8+4 二采。

已经完成真实 H3 文生视频（T2VA）和首帧图生视频（I2VA）短片对照及人审，画面被接受为相近可用。新节点为 `MiniMaxH3ProgressiveSamplerEXPT8`，随 1.77.0 以 EXP 提供；旧节点及工作流不变。游戏声音仍有差异，不能当成所有画面和声音都通过。

## 当前用法范围

工作流位于节点项目的 `examples/workflows/28-progressive-sampling/`。将其中 T2VA 或 I2VA 的 JSON 拖入 ComfyUI 即可；它们是可打开的前端工作流，不是 API 文件。当前按 EXP 提供，不代表所有原计划路径都已验收。

原生 H3 模型与已有 Conditioning → Setup 选择 `euler` 和 `native_flow` → 渐进首采 → 原生 AV Decode。

- `model/sampler/sigmas`：连接同一个原生 Setup 的输出，不能混接。新功能要求当前 Core 的原生 AV 支持；旧 Core 继续使用旧工作流。
- `av_latent`：Conditioning 产生的空音视频潜空间。不能接已采样的结果或遮罩。
- `positive/negative`：目标画幅条件。当前只支持 T2VA 和单张首帧 I2VA，不支持多参考、尾帧、区域控制或音频锁定。
- `upscaler_model`：明确选择 `ComfyUI/models/latent_upscale_models/minimax_h3_latent_upscaler_3d_fp16.safetensors`。复用现有二采的模型，不需要再转换一份；模型不随节点提供。
- `low_evaluations`：小画幅采样步数。例如总共 8 步、这里 6 步，放大后还采 2 步。至少留 1 步，不能选 8。
- `low_scale`：小画幅宽高比例，会对齐到 32 像素。0.5 不代表总时间或显存只有四分之一。
- `task`：文字生视频选 `t2va`，首帧图生视频选 `i2va`。首帧低分辨率条件由 latent 缩放，高分辨率用原条件；不是重新编码低分辨率参考图。
- `seed/cfg`：两组对照保持相同，但不同分辨率的初始噪声张量并不相同。高分辨率视频重新加噪使用 seed+1。
- `precision`：只控制学习型放大器计算精度，不改变主 H3 模型精度。
- `reserve_vram_mib`：阶段边界和回调的空闲显存检查，不是连续峰值监控，也不保证不会 OOM。

这条路线的声音会继续联合采样，不会像现有“锁首采声音”的二采工作流那样保持音频不变。需要重新检查音乐、人声、音量和口型。

当前不与 VDN、FAST H3、SPEED、未知模型包装或区域遮罩混用。拒绝时请保留原节点，使用独立的原生模型分支，不要删除全局 Sage 设置来绕过错误。

## 哪些已验证，哪些还没有

已验证小型随机 H3 的真实 Core Euler 执行、2/4/8 步、音频续采、首帧条件、计数和异常隔离；本机实际学习型放大权重也通过 CPU 接入。报告分别记录回调、模型调用和 H3 网络前向数，不能只看进度条判断工作量。

本机 RTX 4060 Ti 16GB、当前 Core、同模型和新版 EMA B、1024×512、73帧的单组实测：T2VA 原生8步约131.9秒、渐进6+2约85.2秒；I2VA 约144.8秒、93.7秒。两组都减少约35%端到端时间，计入加载、放大切换、解码和保存，无图缓存。它们是进程冷启动、文件缓存已预热的单组结果，不是重复统计或通用加速承诺。

两组均核对了真实8次或6+2次网络执行、259个EMA补丁和完整音视频文件；渐进组确实加载了322张量的学习型放大器。T2VA 首组整体人审通过，不能扩展成所有素材或每项独立评分；I2VA 无对白，只检查参考一致性、运动和环境声。

2026-09-10 又完成了同一进程内的热复测：先各预热一次，再按原生、渐进、渐进、原生执行，关闭图缓存。每路只有两个正式样本，以下是中位数，不是普遍加速承诺。

| 固定短片 | 原生 8 步 | 渐进 6+2 | 总耗时减少 |
|---|---:|---:|---:|
| T2VA | 126.15 秒 | 79.03 秒 | 37.35% |
| I2VA | 139.41 秒 | 86.50 秒 | 37.95% |

热测输出与之前对应的两组视频逐字节相同，所以不需要重复审同一份视频。T2VA 沿用之前的整体反馈；I2VA 后续已单独人审，画面相近、两路环境声正常，不用于验收口型。计时记录在研究目录的两份 `warm-gpu-*-abba-20260910-v1/RESULTS.md`。

已补 CUDA 分配器计量，但本机使用 `cudaMallocAsync`，这些数值代表默认分配池，不是整套模型显存。不能据此宣传渐进更省显存。整卡和系统 RAM 的周期观察也不等于精确瞬时峰值。

固定人物和游戏多 seed 探索的十条新增短片已生成人审：画面全部相近可接受，两组人物音乐、人声和口型正常；三组游戏仍有声音轻或缺脚步声反馈，其中第一组选项与备注指向不同侧，待澄清。游戏三组 A 均为渐进，B 均为原生基线；不能将 B 的问题直接归咎于渐进，也不能擅自归因于模型。另完成一组 MODEL 分支内的 Sage 对照：实际调用 Sage，无 PyTorch 回退，约 106.70→74.71 秒，人审画面相近、声音与口型正常；这组含相同的函数计数开销，不代表所有全局 Sage／第三方插件组合都验证过。

32 秒、0.5MP 的原生基线两次在首次计算时触发显存余量保护，尚无合格长片，也未运行渐进长片。当前不承诺这套 16GB 配方能直接生成 32 秒；继续调预留量没有解决问题，需要另行验证降低实际工作集的方法。

开发基线全仓 CPU 回归 3779 项通过，后台 Core API 对工作流参数和连线的检查完成；这些不能冒充完整浏览器打开/保存/API 导出往返，后者尚未完成。可拖入的两份 EXP 工作流已在项目 `examples/workflows/28-progressive-sampling/`，不需要你导出 API 才能获得。后续 GPU 严格串行，未通过的长片或质量路径不标正式。
