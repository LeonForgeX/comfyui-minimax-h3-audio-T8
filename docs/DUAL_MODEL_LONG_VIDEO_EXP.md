## 接线与参数

工作流文件夹内附有[KJ/Sol接线示例](../examples/workflows/04-long-video/DUAL_MODEL_ACCELERATOR_CONNECTIONS.md)，包括具体节点类、先后顺序和已验证配置。模板不强制安装这些外部节点。

两路都是“底模 → 该路自己的 LoRA → model_pass1 / model_pass2”。
可以共用同一底模、分别选择 LoRA，也可以另接兼容的原生 H3 底模。
本模板不使用 VDN；VDN 的8+4不是本节点的4+4。

- `low_width / low_height`：一采的画幅。模板512×256。
- `width / height`：最终画幅。模板1024×512。
- `coarse_steps=4`：一采使用完整8步表的前4步，但交给放大器的是预测的干净潜空间 x0，不是带噪声的中间结果。
- `refine_steps=4`：二采按独立模型的双时钟和既有放大细化时间表执行4步，结束于sigma0；不是简单复制一采时间表的后4个数。
- `second_audio_source=auto`：4+4由二采继续完成音频；只有完整Stock20一采才默认锁定声音。旧候选4+4的first_pass/0设置自动迁移并记录，避免提前冻结半成品音频。两种分辨率的续段均使用最终音频。强度参数在auto/native legacy模式下不覆盖原生遮罩；口型与内容仍需看真实成片。

续片时，二采只在原生遮罩为0的位置使用高分辨率条件中的已知声音；可采样位置保留本段一采结果，再由二采完成，不会因一小段上下文而替换整条音频。低、高两路下一段上下文都保存最终二采声音。该修正已覆盖CPU测试与真实8秒两段中断恢复，画音人审及更长链仍待。
- `coarse_steps=20`：为原始Stock20及EAV保留；4+4时EAV必须关闭。
- `chain_id`：断点任务名字。修改提示词、模型、LoRA、时长或尺寸时换一个名字；不手动混用不同任务的缓存。

两份JSON在 `examples/workflows/04-long-video/`，直接导入。节点自己保存并预览视频，
不需要从前端“导出API”才能使用。基础图用global_prompt；Relay图每行一个局部事件，
并按时间范围投影到各段。改变总时长，也要同步Plan的length。

全局提示词会用于每一段，不是一次性执行的完整剧本。模板将稳定场景/音乐留在全局，
单次对白只写进Relay第一项局部事件；基础图默认纯音乐。
修复后的24秒六段链已完成576帧及音画完整解码检查：已知音频上下文保持不变，
本段新声音继续二采完成。23秒抽帧仍可见不需要的字幕状文字，尽管提示词明确禁止文字。
这是真实存在的质量问题，不能裁掉后当作通过，也尚不能确定是模型能力还是其他原因。
仍需完整听看事件跟随、对白出现次数、音乐、口型和接缝。

## 同条件后端实测（单机少量观测）

以下表格来自音频修复后的六次同条件运行，旧锁音频样本及被其他音乐任务干扰的一组已排除。
三后端统一禁用锁页、reserve-vram=5、vram-headroom=2；未修改用户启动配置。
当前增加模型本地计时：初始采样准备、前向、两采、放大、AV解码、trim、候选保存和最终封装。
这些是主机调用墙钟时间；动态搬运可能包含在前向中，各层区间也会嵌套，不能相加成纯GPU耗时。
复用缓存时，旧阶段报告只是来源记录，不计作本次新采样。

RTX4060Ti16GB；固定Core488e8f8、Torch2.10.0+cu130；同一FL2VA底模、两路EMA B、
seed、提示词、512×256→1024×512、3秒4+4。每个后端新进程首次运行一次，随后在同一
进程再完整运行一次。关闭节点缓存，并更换链名防止复用已生成阶段；正常阶段卸载仍保留。
