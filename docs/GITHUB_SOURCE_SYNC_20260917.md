## 为什么正式目录会与线上不同

此前有更新从独立本地发布树推送，但正式目录只回写了部分版本说明和配置；
例如正式 Topaz 五个运行模块仍对应 v1.79.6，而线上已含后续自动交付和参数说明。
这属于正式部署回写不完整，不是 GitHub 自行生成了较新代码。
版本号、Git HEAD 和磁盘上的实际运行模块必须分别核对。

## 后续防回归门禁

1. 固定真实线上 SHA，按已完成源文件白名单合并；先查其他任务的未完成准备件。
   不整棵复制研究目录，不使用 `git add .` 包含脏目录，不强推覆盖线上历史。
2. 核对实际注册顺序、Core 输入／输出与已保存图；回归缓存身份、原 callable 保留／委托、
   真实错误传出，以及[五项长视频接缝门禁](DUAL_MODEL_SEAM_FIX_20260913.md)。
3. 线上已有修复的代码和测试一起保留。测试只能更新真实的策略／追加注册断言，
   不删数值、损坏 receipt、坏哈希或真实 kernel 异常用例来制造通过。
4. 正式目录同步前备份目标文件并检查同步期间没有其他任务修改。
   逐文件比对实际内容；故意保留的历史默认差异要明确记录，不能宣称整棵目录完全一致。
   不 reset 用户 index，不删除根目录旧兼容入口，不重启用户正在使用的 ComfyUI。
5. 推送前、推送后都检查候选文件清单和全部祖先历史不含 ROADMAP；
   核对远程提交 SHA。源码更新不冒称 Registry 已发布或已激活。
