# SelfLift 原生渐进接口修复（2026-09-17）

## 原因与修复边界

此前单列的5项失败不是缺少依赖，也不是Sage/Sol或LoRA被证明不可用：
调用方已经传入 `checkpoint`、`producers`、`eav_tau` 等配置，正式目录的
`sample_progressive_h3` 却仍是旧的基础首采接口，直接产生参数 `TypeError`。
其中3项是TST MODEL逐阶段配置的参数化用例，另2项检查真实producer与缓存身份。

本次显式补齐参数并接入原生执行，不采用 `**kwargs` 吞掉配置。
默认空AV、单MODEL、EAV/TST关闭的旧执行路线保持；可选组合进入独立的
`progressive_sampling_composed.py`，不整体恢复暂停的Meridian/H16/Semantic Bridge。

- checkpoint：只持久化真正完成的LOW边界视频预测和下一时刻音频状态。
  恢复后HIGH接续原完整sigma表；报告区分本次前向与历史已完成LOW，不伪造计数。
- producers：核验实际CLIP／VAE输入来源并绑定缓存身份，采样前后复核。
  伪造来源标签、坏SHA和损坏缓存仍报错。
- LOW／HIGH MODEL与TST：分别消费本路配置、保留LoRA链和既有callable，
  TST使用完整时间表的阶段区间，HIGH不重新启动步数时钟。
- EAV／Relay：为两个空间网格重绑定自身布局，保留事件与音频时间坐标；
  内部原生8步／初始化遮罩合同只供对应渐进执行器使用，不改变独立EAV的旧默认配方。
- 接缝与默认数学：不修改已验收双模型长视频的上下文、音频、sigma、拼接或3D网络。
- 不透明MODEL身份：每次检查生成的不可移植nonce不等于用户更换了模型。
  同一NativeProgressiveJob按真实对象／权重复核；持久身份仍保留初始nonce，
  不给未知组合跨运行缓存复用许可。真实权重、输入和配置改变仍报错。

## 使用与验证

正式目录的原渐进单段节点末尾追加可选HIGH MODEL、首帧缩放策略与EAV参数；
原required输入位置和缺省采样配方不迁移。公开单段空AV输入范围不扩成任意编辑器，
续段由现有Progressive Long Video节点管理。已有工作流文件不重新生成或替换。

用户自选Sage／Sol／LoRA／wrapper不因“组合未验证”被禁止；执行报告保留真实
覆盖和回退信息。CPU执行、Core图校验、真实CUDA内核与整模型成片人审分别记录。
历史接口修复验证不等于新增GPU质量验收；当前GitHub源码合并范围见
[源码同步说明](GITHUB_SOURCE_SYNC_20260917.md)，不另发布Registry版本。

默认单MODEL路线保留原Core注意力派发，不为获得自有计数偷偷替换用户实现。
显式组合路线记录各阶段delegate的实际完成计数。第三方owner不调用原执行器时，
TST／EAV／Relay覆盖只能报告未验证；缺少真实LOW前向证据不写断点，
但不会仅因覆盖不足禁止执行。内核异常、错误布局、坏输入及坏缓存仍正常报错。

重启ComfyUI才能载入本地Python，启动后先核对节点来源为本项目正式目录，
不要恢复旧release-test禁用副本。ROADMAP只保存在本地，不提交或打包。

跨进程断点测试要求父子进程采用相同CPU线程数，并保留 `rtol=0, atol=0`。
扩展初轮父进程1线程、旧worker固定2线程，出现7/28416个浮点值的
约1.49e-8差异；不改生产数值路径，先将父进程设为2线程作控制，原样worker
对照逐位通过。随后worker继承父线程数，最终断点／Relay测试复验。
这不是通过放宽误差掩盖断点问题，也不承诺不同设备／线程／内核间逐位一致。

## 防回归

调用方新增可选参数时，必须同步检查执行器签名、真实阶段执行、schema与缓存身份。
至少覆盖旧默认逐位一致、参数实际生效、producer变更不误复用、LOW断点真实恢复、
逐阶段TST／EAV／Relay、前置补丁保留与真实异常传出。不能只通过注册或图加载检查
就声称执行接口正常；也不能删除失败测试或用忽略参数代替功能实现。
