## 采样与接线

渐进节点使用一张完整的原生 Euler 时间表。总8步、`low_evaluations=4`表示低分辨率4步，
学习型3D latent放大，然后完成剩余4步；`low_evaluations=6`为6+2。
这不是原双 MODEL 长视频节点的独立二采时间表，也不是VDN8+4。

两路分别配置：

- LOW：原生H3底模 → 本路兼容H3 LoRA链 → 本路一个注意力后端 → `model`。
- HIGH：同一或兼容底模 → 本路兼容H3 LoRA链 → 本路一个注意力后端 → `model_hires`。
- 不接`model_hires`则沿用LOW配置；不能通过在LOW链后再叠加LoRA来获得独立HIGH配置。
- 两路架构、latent格式、视频/音频shift及音频尺度必须一致。权重可以不同，但兼容形状不保证画面风格或人物连续。
- 旧单段 `MiniMaxH3ProgressiveSamplerEXPT8` 的公开输入仍要求空原生AV潜空间。
  新 `MiniMaxH3ProgressiveLongVideoEXPT8` 在内部管理首帧、续段条件和阶段缓存，已有两段8秒机械证据；
  它不公开任意初始化AV、多参考或通用编辑输入，不能以内部测试接口代替公开支持范围。

Core注意力选择、指定已审计KJ Sage/省显存/FFN组合、指定`SolAttentionPatch`分别是可选路线。
不要串联多个attention替换器。Sol在偏置、不等长Query等情形会明确回退；这不是稀疏加速证据。
Core Sage报告中的delegate调用也不等于独立证明底层CUDA内核无回退。
对不接收Relay偏置的Core自动Sage版本，渐进组合器仅将有偏置查询交给已审计的
Sage Triton作用域内核，保留自然对数偏置到log2的换算；`scoped_masked_sage`单独报告实际调用。
找不到已审计的偏置内核时保留明确的SDPA回退原因，不丢弃偏置，也不假报Sage执行。

## Prompt Relay

单段采样接口的LOW应接当前Prompt Relay Conditioning节点的配对MODEL与positive输出，`cfg=1`。
其HIGH可以接未绑定Relay的独立MODEL，或相同绑定的Relay MODEL；不同剧本/时间表的两路绑定被拒绝。
新Long节点则直接接全局 `prompt_relay_plan`，内部按每段和两个画幅准备条件；不要额外给它叠加另一套已绑定Relay MODEL。

节点会核对原目标画幅，再给LOW和HIGH分别建立精确packed layout及配对hash。
只改变空间网格；局部事件时间、文本token范围及音频时间坐标保持不变。
`video_only_paper`只直接路由视频Query；`joint_av_exp`同时路由目标视频与音频Query。
全局提示词放持续的人物/衣着/环境，单次对白放对应局部事件，不能重复写入全局。

执行报告分别记录每阶段的完成前向数与真正经过Relay路由的主注意力次数。
错误配对、目标尺寸漂移、丢失主网络路由会报错，不删除时间偏置来换取速度。

## EAV

使用渐进节点内部的`eav_mode`；不要把已经装有独立EAV包装的MODEL直接接进来。
内部显式组合器让EAV与Relay共同拥有一个网络入口，不放宽原有的冲突检测。

| 参数 | 含义 |
| --- | --- |
| `eav_mode=disabled` | 默认关闭；不安装EAV，不修改采样张量 |
| `report_only` | 计算并报告CFI和增益，但不应用增益；CPU对照要求与关闭时逐位一致 |
| `apply_exp` | 实际对目标视频attention输出应用FETA增益；后续联合层仍可能间接改变声音 |
| `eav_tau` | 增益公式中的调节量；0不代表关闭 |
| `eav_start_video_progress` / `eav_end_video_progress` | 使用`1-原生视频sigma`，不是当前阶段的步数百分比；HIGH不会从0重新开始 |
| `eav_max_workspace_mib` | CFI分块计算预算，不是整机显存上限 |
| `eav_g_hard_limit` | 增益超过上限中止；不静默截断或重试 |

当前新增范围是完整8或20步、CFG1、T2VA/单首帧I2VA。完整表必须从1到0，LOW至少1步，HIGH至少1步。
每阶段的实际sigma、进度、帧数、空间网格、音频范围、前向和主块测量次数都单独核验；
两阶段合计必须对应原完整时间表。即使某阶段没有落入EAV窗口，也仍核验该阶段的采样执行。
若全程没有激活EAV，报告明确写`inactive_window_no_enhancement`，不声称增强生效。

这是新的渐进EAV8实验，不是解除原双MODEL长视频的Stock20限制。
原长视频4+4流程目前仍不能通过直接打开原EAV开关来获得这一新增组合。

### 整条音频与每段音频（内部任务接口）

`NativeProgressiveJob` 的 `shared_condition_options` 接受全片共用的条件选项。
其中 `drive_audio`／`final_audio` 被视为整条输出时间轴音频：每段按
`timeline_start_seconds - context_frames / 24` 开始，截取完整 render window，
源不足时仅补零，不循环，不改变采样率。切窗复用已有长视频实现，一次只准备当前段。
`audio_mode=reference_only` 的 drive_audio 是音色参考，保持原对象，不按时间轴耗尽。

已有 `segment_condition_options[index]` 仍表示调用者已经选好的局部条件／音频；
显式局部字段优先于同名共享字段，局部音频不再切窗。局部 `None` 可以取消同名共享输入。
因此不能把整条音频放到每段局部输入后期待自动裁切。
共享尾帧只交给最后一段；首帧复用与身份策略仍由原条件构建器处理。
参考视频／参考图片不是输出时间轴源，不会在这个辅助层被自动切片；原有任务支持检查仍有效。

`delivery_audio(index, generated_audio)` 在实际任务锁下，从内容绑定的输入重新选择输出：
显式 `final_audio` 优先；否则 native／lock_source 使用 drive_audio（若连接）；
reference_only／remix_source 使用生成音频。返回来源与实际内容身份，完成 latent 缓存命中后也可重建。
这些规则与原条件构建器一致，不把音色参考或重混的源音频误当最终音轨。
共享输入全内容纳入 job 身份，源音频／选项发生变化不能复用旧任务。

下述内部封装已接入自动解码、机械接受、拼接和最终媒体恢复，但仍需完整模型组合验证，
不能替代新成片的人审。
新增媒体选择、首段采样／恢复和旧循环合计51项CPU回归通过；首段执行使用真实小型H3/Euler，
编码器及学习型放大器为明确测试替身，不是完整权重的视频质量证据。

### 自动交付链（内部候选接口，CPU交付验证通过）

`ProgressiveChainDelivery(job).run()` 接收已绑定实际模型、编码器、时间表和源媒体的
`NativeProgressiveJob`。只在 ComfyUI 配置的输出目录下工作，复用同一条链的独占锁；
不修改全局输出目录，不替换旧长视频节点。当前固定24fps、8bit H.264/AAC交付。

每段流程为：首段／续段采样及其已有阶段缓存 → 原生AV解码 → 原输出音轨选择 →
裁掉上下文并限制到计划时长 → 原候选MP4／39帧容量上下文保存 → 内容绑定回执 →
原子接受。所有片段就绪后调用原逐帧流式拼接器。这里的“接受”只是机械执行状态，
结果始终标记 `human_qualified=false`，仍需完整动态审片。

- 在候选回执完成后、接受前中断：验证候选与源任务后继续接受，不重新采样或解码。
- 在最终拼接中断：已接受片段保留，继续拼接，不重跑片段。
- 最终回执存在：重新校验任务、交付设置、全部候选／接受媒体与最终文件哈希后复用成片。
- 半成品没有完整回执：保留旧文件，新的编码尝试使用新候选名；不覆盖或盲目采用残留物。
- 修改编码设置／前缀／音频接缝策略后用新链；坏回执、坏哈希、外来接受片段立即拒绝。
- 主清单损坏或只有旧备份时不静默回退，以免丢掉最后已提交片段；需先明确恢复主清单。
- 写入锁／回执／候选／接受文件前，检查对应目录和目标路径仍在链目录内；拒绝越界重定向。

此封装不增加视频叠化、颜色修正或latent桥，不修改HIGH遮罩、音频latent和3D放大器。
真实编码／拼接和中断恢复已通过CPU测试；尚不能把该封装算作完整权重GPU成片通过。
目录边界检查加入后，交付、实际任务恢复与旧双采接缝／工作流合计108项回归通过，
包括实际192帧两段MP4、接受／拼接中断、最终复用和真实目录重定向拒绝。
随后补严了最终复用前的接受文件路径非空／上下文存在性检查，11项聚焦检查通过（与前述有重合）。
交付测试的采样和VAE解码为明确替身；实际tinyH3采样恢复测试另有覆盖，两者不冒充
同一次从完整权重生成到成片的端到端验证。所有新片质量仍需真实模型生成与完整动态人审。

### 实际条件与交付报告绑定（内部候选）

首段及续段统一输出 `prepared_delivery`：实际条件构建器返回的 conditioned_prompt、
媒体标签表、条件报告，以及所选 mux_audio 的全内容身份。续段的这些值纳入准备输入身份，
生成过程中被修改会拒绝继续。交付不再用原始 segment_prompt 冒充实际带参考标签的编码提示词。
候选恢复时核对保存提示词；交付时核对显式音频身份，生成音频路线则必须没有外接mux覆盖。
这不重新编码提示词、不改音频、不改变生成数学，只让持久报告绑定真实执行输入／输出选择。

两种同一次整链CPU验证已通过：T2VA＋联合音画Relay＋EAV＋显式最终音轨；
I2VA＋video_only Relay＋EAV＋锁源音频。原生小型H3/Euler、任务／阶段缓存、AV解码封装、
候选／上下文、MP4拼接连续执行，编码器网络与学习型放大器仍为明确替身。
这两条均完成192帧媒体与音频解码；T2VA另验证后段HIGH中断后仅执行剩余HIGH阶段，
两条最终媒体恢复均逐字节一致且不再次采样／解码。与三项准备报告篡改拒绝检查同批5项通过。
不把随机小模型、替身VAE输出当作画质或完整模型验收。

另有3项原生续段组合测试通过：PyTorch、已安装KJ省显存定义、已安装Sol选择器。
每路LOW／HIGH各串联两个真正的Core LoRAAdapter，使用不同权重和强度；
在实际网络前向入口逐次核对应用后的权重与独立矩阵乘法预期值，而非只数补丁条目。
同时验证联合Relay、EAV、原生续段遮罩和实际4+4前向。CPU回退如实记录，不是Sage／Sol的CUDA提速证据。

内部`input_mode=initialized_av_exp`允许有限值原生AV源；默认`empty`继续拒绝非零源和遮罩。
输入时间表可从`0 < sigma <= 1`开始，必须严格递减到0并至少保留各阶段1次前向。
完整表从1开始时，原生flow会抹去未遮罩区域的初始化内容；这不是有保留强度的img2img。
需要初始化内容影响自由区域时必须显式提供部分时间表，不能只接非零latent便宣称在细化原片。

遮罩`1=生成、0=保留`，普通张量只控制视频，音频仍为全生成；联合遮罩可分别控制音视频。
视频时间只能为1（逐帧广播）或精确latent时间长度；音频时间同样不做隐式拉伸。
空间缩放调用Core原始运算顺序，避免“数学等价”的二维插值引入不同fp32舍入。
重复的完整通道遮罩可以输入；不同通道的不同遮罩尚未支持，不能静默挑第一个通道。

两个状态必须独立：

- HIGH求解器仍从LOW预测、原有学习型3D放大和原生音视频状态重建获得带噪起点。
- HIGH的已知区域始终绑定原始目标尺寸的干净AV源，不使用带噪起点或LOW半成品充当干净参考。

实现仅在本次原生Euler的临时`KSamplerX0Inpaint`对象上绑定干净源与条件噪声，
保留Core输入注入、2×2视频token遮罩、音频尺度/时间转换及输出约束；结束或取消时恢复临时对象。
这不是采样后修补画面或简单post-CFG锁定，也没有增加扩散前向数。

CPU对照覆盖全已知/全生成/前缀/分数遮罩、部分时间表、原生输入张量与条件、取消重用、
Relay以及两路各两层真实Core LoRAAdapter计算。Sage内核仍用明确标注的CPU测试替身，
Sol在CPU走明确报告的fallback；这些不构成CUDA加速或训练权重画质验收。

初始化AV与EAV已增加内部显式组合器（仍未开放为正式节点用法）：

- LOW/HIGH分别绑定各自精确画幅、音频形状、原生token遮罩及内容hash；每次前向都核对实际接收到的遮罩。
- 支持完整或显式部分时间表；进度仍为`1-sigma`，HIGH不重置，步数与原时间表逐段核验。
- FETA沿用整个目标视频网格的CFI/增益定义，包含已知和可生成帧，不冒称“仅统计自由区域”。
  原生H3仍负责已知区的输入注入和最终约束；后续联合层可能间接影响自由音频。
- `report_only`与关闭时要求逐位相同；全已知区域即使内部计算了增益，最终仍受源内容约束，不能据此声称画质改善。
- 新的内部profile不加入原EAV节点的选项，不放宽旧Stock20、参考块、STG或原长视频组合的保护。

公共初始化接口尚未接入前段来源、视频VAE续段构建和恢复身份，不能据此宣称“长视频已经支持”。
既有通过样片的LOW参考来源、HIGH遮罩、音频和缓存路径没有迁移到此接口。
