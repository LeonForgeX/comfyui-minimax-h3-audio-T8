# 曜石导演台 D1：项目、素材与编译预检

这是本地开发阶段的真实 ComfyUI 界面，不再是 File/Blob 临时素材原型。
保留暂定 v4 的曜石布局与交互。D1 项目／预检层本身不加载模型；当前页面的 D2 生成按钮会通过独立的
原生 Core 服务提交已验证的 H3 图。预检通过只表示项目与引用合同可编译，不表示模型兼容、显存安全或成片画质通过。

## 怎么使用

1. 重启 ComfyUI 加载本地 Python 更新，刷新前端。在 ComfyUI 左侧栏点击独立的 **导演台**。
   也可以添加 `曜石导演台 / Obsidian Director D1 (T8)` 节点，再点“打开曜石导演台”。
2. 默认使用新手模式：全片设定单独写，其余提示词整段粘贴到左侧完整提示词区。
   高级模式可分别编辑整镜描述与时间事件；两份草稿保留，只编译当前写法。
3. 左侧“添加到本镜”统一上传图片、视频、音频。上传成功才显示卡片。
   卡片直接指定首帧、尾帧、参考、音频驱动或参考音色，也可排序、插入引用和删除引用。
   全片共享置顶，编号按图／视频／音频分别从 1 开始；插入不覆盖原文。
4. 点击 **保存项目**，项目与素材身份保存到当前服务器。“打开项目”可以恢复。
   每个标签独立保留未提交草稿；另一个标签已保存时会提示冲突，不静默覆盖。
   可另存副本，或导出当前稿备份后重新载入。保存／上传失败可保留草稿后重试。
5. 点击 **检查准备情况** 或 **编译预检**，查看实际提示词、别名与原生素材槽映射、
   时间与帧对齐、声音用途、输入预览和错误。通过后可导出 CPU 预检工作流与 API 快照。

“返回画布”只关闭导演台，不代表取消任务。D1 自身没有生成任务可取消。
通过节点打开时优先恢复该节点内的项目快照；保存才更新节点，未保存修改不会偷偷覆盖快照。

全片设定下方的“模型、LoRA 与分辨率”是全片默认配置：模型与两个 VAE 选择“自动”时按镜头类型挑选已安装的 H3 文件；LoRA 可逐条添加、设置强度、禁用或移除，提交时按列表顺序串联。0.4–0.8 MP 会按当前画幅换算为总像素，并自动对齐到 32 的倍数；实际值可在预检报告查看。

右侧 D3 选项默认勾选“使用全片默认配置”。取消后仅当前镜头覆盖全片设置；再次勾选会恢复继承。底部“按顺序生成全部”会逐镜提交并等待上一镜完成，任一镜失败或取消就停止后续镜头，不会重复提交。

## 三种导出文件，不要混用

| 文件 | 用途 |
| --- | --- |
| `director.project.json` | 可继续编辑的项目；含素材稳定身份、两份提示词草稿与引用映射 |
| `director-d1-preflight.workflow.json` | 原生 ComfyUI CPU 预检图；可以在画布打开、保存、重载 |
| `director-d1-preflight.api.json` | 对应 CPU 预检节点的 API 快照；不是 GPU 生成配方 |

目前工作流只有 D1 预检节点，不包含 H3 采样或成片保存节点；真实生成属于 D2。
未知旧工作流不会被猜测转换或覆盖当前项目，可下载原始字节并返回画布打开。

## 素材与恢复

素材复制到当前 ComfyUI 的 `input/t8_director/<UUID>/`；同名文件拥有不同身份。
项目／资产清单位于当前 `user/t8_director/`。自定义 input/user 目录时跟随实际配置。
浏览器用当前服务器的 URL 和 UUID 访问素材，不把本地盘符或 blob URL 当作远程输入。

文件缺失或字节变化会明确报错。上传大素材会显示进度，只有服务端完整注册后才加入项目；
点击 **重连缺失素材** 选择原卡片，再上传同种媒体，
显式将各镜头引用更新到新身份；不覆盖旧文件，可撤销。素材库中已经退役的缺失资产
可以保留供撤销，不阻断已重连项目；仍被引用的缺素材必须处理。
删除镜头或引用不会删除电脑文件、素材库文件或已生成作品。
单素材上传最多 1GiB，超过时失败提示，不截断；不支持的格式请先转为标准图片／MP4／WAV。
上传进行中可主动取消；取消、断线和超时都不会把未确认的半文件加入素材库。

## 编译规则

- `@imageN/@videoN/@audioN` 是编辑器别名，按稳定身份转换为 `<Picture N>/<Video N>/<Audio N>`。
  显示顺序不等于原生槽顺序：首尾图、视频自带音轨、独立音频均参与实际映射。
  引用未分配用途、已删除素材、越界原生标签或损坏别名清单时不会悄悄改指另一素材。
- 全片文字只合并一次；隐藏写法不执行。新手原文不自动拆句、不猜自然语言时间。
  高级事件需明确开始／结束，落在 24fps 帧网格，不暗中舍入。
- 实际画幅以预检里的宽高为准，模型尺寸 32 对齐可能与名义比例存在小差异。
  首尾图片执行 EXIF 转正、RGB、等比缩放及黑边填充，显示真正的 CPU 输入；不拉伸人物。
  原文件不变，派生预览具有源与输出字节校验。其他参考的完整送模预处理仍在 D2 接入。
- 时长按 24fps 与 H3 的 `17n+5` 网格回显请求帧数、生成帧数和交付长度，不新增生成帧数上限。
  9 张参考图／3 段参考视频／3 条独立参考音频是素材槽限制，不是视频帧数上限。
- **原音驱动**：只选择独立单段 Avatar 首帧配方；原录音选区用于驱动和原声交付。
  复杂多参考／尾帧组合请回高级画布，D1 不冒充其已验证。
- **参考音色**：用参考音频生成新台词，走原生声音模式，不接驱动或原声交付槽，
  不把参考原声贴回结果，也不保证声纹完全一致。

## D2／D3 当前状态

当前正式目录已经包含 D2a–D2c 的真实 Core 生成桥接：文字／首帧、首尾／尾帧／参考图、原音驱动、
参考音色都会编译成原生 H3 图，并由明确的“生成当前镜头”按钮提交；进度、结果播放、仅当前任务取消和
断线轮询使用同一个 prompt ID。D2 的 GPU 机械成片收据已完成，画面、口型、音量、接缝等感知验收仍以
用户实际素材为准。

D3 面板中的 Semantic Bridge、Prompt Relay、FastH3 V2、LowVRAM Attention、ChunkFFN 已进入真实图编译。
启用 FastH3 时会选择专用 `fastvideo_fasth3_8step_v2_pruned_int8_convrot.safetensors`，不会再叠加普通 Turbo LoRA；
这些路线均有依赖门禁，缺模型会在排队前报错。FastH3＋LowVRAM＋ChunkFFN 已在隔离 GPU 完成 96 帧／4 秒
短片。D3 预检中的每条长片／二采、EAV、TAEH3、Topaz、Meridian 路线可下载仓库内核验的原生工作流／说明副本，
但不会伪装成导演台内的一键图编译；Semantic Bridge 未安装权重时也会明确阻断。

H16-3 的 `DeciiaChunkedPass2Sampler` 已作为正式目录的独立实验节点注册，可直接替换外部
PASS 2 的同名采样口；默认保留一采音频，需显式选择 `refined_exp` 才启用绝对时间轴拼接、
重叠交叉淡化与安静尾段保护。73 帧资格样片已完成真实 GPU 与用户音画验收；该结论不外推到其他
素材、尺寸、时长或分块参数。使用说明见
[`H16_3_CHUNKED_PASS2_EXP.md`](H16_3_CHUNKED_PASS2_EXP.md)。

Topaz 的 D3 预检还会只读发现本机正式安装：优先检查 `Program Files/Topaz Labs LLC/Topaz Video AI`
及 `ProgramData/Topaz Labs LLC/Topaz Video AI/models`，盘点程序文件、JSON 定义和候选权重数量。
这只改善“是否有可继续的原生运行时”提示，不启动 Topaz／FFmpeg、不读取授权、不下载模型；正式环境节点仍必须
按签名、滤镜接口和实际模型加载合同执行。新版 `Topaz Video AI.exe` 与旧 `Topaz Video.exe` 文件名均可识别。

对于尚未做一键图编译的原生路线，D3 预检会显示该路线的继续步骤、必需材料和执行边界，
并提供“导出当前镜头路线包”。路线包是可审计的 JSON：包含当前 `director_project` 快照、
稳定素材身份、仓库内原生工作流／README 原文及 SHA256；它不复制媒体、不改写原生工作流，
也不自动排队。下载后在 ComfyUI 画布打开对应工作流，按包内 contract 补齐外部模型／运行时，
再由原生节点做最终检查。

## D4 浏览器验收

独立 CPU Core 的真实 Playwright 回归已通过：Canvas 入口与 iframe、图片／视频／音频混合上传、首尾／参考／
参考音色分配、删除与撤销、服务端 CAS 保存、跨标签冲突与另存、刷新草稿保护、原生工作流往返，以及
1440、1060、750、390、320 五种窗口宽度均通过；测试期间 `/prompt` 提交为 0。大素材上传的进度、取消和
离线草稿保护也保留在正式前端。该收据是机械／交互验收，不代替 GPU 成片画质或新手人工验收。
